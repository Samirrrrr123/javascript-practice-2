# Практическая работа №2 — Vue и авторизация

Учебное приложение по предмету «Проектный семинар с фреймворками JavaScript».
Используются Vue 3, Vue Router, Vite и Fake API DummyJSON.
Внешний вид сделан по скриншотам макета Auth pages template.

## Запуск

Нужны Node.js 22.12+ и npm (npm устанавливается вместе с Node.js).
В терминале из папки проекта:

```bash
npm install
npm run dev
```

Открыть адрес, который появится в терминале (обычно http://localhost:5173).

Проверка сборки:

```bash
npm run build
npm run preview
```

При использовании pnpm: `pnpm install`, `pnpm dev`, `pnpm build`.
В репозитории сохранён `pnpm-lock.yaml`, фиксирующий проверенные версии пакетов.

## Страницы и выполнение задания

| Адрес | Что делает |
| --- | --- |
| `/home` | Описание, картинка, кнопка перехода на `/login`. |
| `/users` | GET `https://dummyjson.com/users`; имя, фамилия, maidenName и почта. Вход не нужен. |
| `/login` | Форма логина и пароля; POST `https://dummyjson.com/auth/login`. Ошибка сервера показана красным внутри формы. |
| `/profile` | Приватная страница. GET строго `https://dummyjson.com/auth/me` выполняется внутри компонента с заголовком `Authorization: Bearer <token>`. Показывает данные пользователя и его картинку. |

После успешного входа `accessToken` из ответа сервера сохраняется в
`localStorage` под ключом **token**. Роутер проверяет этот ключ перед переходом
на `/profile`; без токена открывает `/login`.
Наличие токена ещё не означает, что он правильный: если API отклонит токен,
сообщение сервера появится в **заголовке Profile**. При ответе 401 старый токен
удаляется, но ошибка остаётся видимой на текущей странице.

Данные не подставляются из макета: список, профиль и аватар приходят от API.
Поэтому имя и изображение могут отличаться от скриншота задания.

## Данные для проверки

В [официальной документации DummyJSON](https://dummyjson.com/docs/auth):

- Login: `emilys`
- Password: `emilyspass`

Можно использовать данные другого пользователя из https://dummyjson.com/users.
Это тестовые учётные записи Fake API.

1. Открыть `/profile` без токена: должна появиться форма входа.
2. Ввести неверный пароль: внутри формы появится красная ошибка сервера.
3. Войти с правильным паролем: откроется профиль с данными и картинкой.
4. Обновить профиль: вход сохраняется, пока токен действителен.
5. Открыть `/users`: загрузится список пользователей.
6. Для проверки неверного токена открыть инструменты разработчика → Console:
   `localStorage.setItem('token', 'invalid-token')`, затем открыть `/profile`.
   В заголовке появится ошибка сервера.
7. Чтобы выйти для повторной проверки:
   `localStorage.removeItem('token')`, затем открыть `/profile`.

## Как объяснить код на защите

- `src/main.js` создаёт Vue-приложение и подключает роутер.
- `src/App.vue` — общие навигация, место для текущей страницы (`RouterView`) и футер.
- `src/router/index.js` — список маршрутов и проверка токена (`beforeEach`).
- `src/views/` — четыре отдельные страницы. В каждой находится её логика.
- `data()` возвращает данные компонента. Когда они меняются, Vue обновляет экран.
- `mounted()` запускается после появления компонента. Здесь загружаются Users и Profile.
- `v-model` связывает поле формы с переменной.
- `@submit.prevent` вызывает `login()` и не даёт браузеру перезагрузить страницу.
- `fetch()` отправляет запрос. `await response.json()` получает JSON из ответа.
- `response.ok` проверяет успешность HTTP-ответа. Сам `fetch` не считает 401 ошибкой JavaScript.
- `try/catch/finally` обрабатывает результат, ошибки и завершает состояние загрузки.
- `v-if` выбирает, что показать: загрузку, ошибку или данные.
- `v-for` выводит карточку для каждого пользователя; `:key` задаёт её уникальный ID.
- `localStorage` хранит токен между перезагрузками страницы.
- Сервер проверяет токен из заголовка `Authorization`, затем возвращает текущего пользователя.


с `createWebHistory` хостинг должен отдавать `index.html` для маршрутов приложения.
